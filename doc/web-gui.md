# Web GUI

Web GUI 用浏览器操作现有 C++ 实验程序，提供参数面板、四轨试听、策略对比卡片、
水位与延迟曲线，以及随播放游标更新的状态和关键事件。默认使用 45 秒中文真人语音。

## 启动

在项目根目录执行：

```sh
make web
```

该命令通过 uv 安装锁定的 `web` 依赖组，构建 C++ 程序，然后启动本地服务。
浏览器打开 `http://127.0.0.1:8765`；终端按 Ctrl-C 结束服务。
服务启动后页面会自动生成一次默认实验，音频需手动点击播放。

```sh
make web WEB_PORT=8787                      # 更换本地端口
make web INPUT=/absolute/path/speech.wav    # 使用其他本地 WAV
make web TUI=OFF                           # Web 界面不需要 FTXUI
```

音频从启动命令指定，不通过网页上传。页面仅向当前本地服务提交数值参数，
不接受任意文件路径或命令参数。音频处理与生成文件均在本机完成。

## 试听与观察

### 先区分预算、含前视的目标水位和实测等待

**左侧的小固定 20ms 是额外抗抖动预算，不是总缓冲等待。** 页面显式展示：

```text
20ms 额外预算 + 40ms 算法前视 = 60ms 目标水位
```

前视（Lookahead）是在处理当前声音前，缓存其后的一小段已到达音频，供波形匹配
和平滑拼接使用。三种策略统一包含这 40ms；固定策略也一样。
左侧输入框下实时显示含前视的目标水位，右侧卡片用本轮实际配置展示计算关系，
再列出实测的平均等待。修改参数后，右侧结果需重新运行才更新。

默认 45 秒语音、`phased`、seed=42 时，小固定的平均等待约 61.5ms；它是有效源
样本“首次输出减所属包到达”的均值，受到达时序和音频拼接影响，不必恰好为 60ms。
这 40ms 是项目的算法余量，并非所有固定缓冲的必然开销。原理见[设计说明](design.md)。

### 操作步骤

1. 左侧选择网络场景、设置延迟和缓冲预算，点击“运行实验”。三种策略共用同一音频
   与网络轨迹；结果生成期间可以继续查看上一轮，失败也保留上一轮结果。
2. 上方选择小固定、大固定、自适应或原始语音，点击播放。切换策略会保留实验时刻；
   不同策略的源游标可能不同，因此同一时刻不一定对应同一音节。
3. 拖动时间线、点击波形或曲线定位；使用前进/后退五秒、循环试听和音量控制。
   波形是原始输入的可视参考，试听的是所选策略真实导出的 WAV。
4. 查看整轮对比卡片中的平均缓冲等待与 PLC 时长，再观察此刻的连续水位、目标水位、
   源位置和累计补静音。FAST、SLOW 和 PLC 各有对应说明。

默认 `phased` 在前 5 秒平稳，5–10 秒随机抖动，10–15 秒周期突发，之后恢复。
可先试听小固定的断续，再比较大固定与自适应的连续性和等待。

## 曲线与统计口径

水位图显示目标水位和实际连续可播水位；目标已包含共同的 40ms 算法前视。
延迟图显示同一批首次贡献源样本的网络延迟、缓冲等待和包发送至输出延迟，满足
`网络 + 等待 = 发送至输出`。无有效源样本贡献时保留空缺，不画成零延迟。

曲线展示整轮结果，白色游标指示当前试听时刻；悬停可查看其他时刻的曲线读数，
点击后才改变试听位置。下方状态与关键事件只显示截至播放游标的已发生数据。
原始语音绕过网络与缓冲，不显示虚构的水位或 PLC 指标。

这些是模拟时钟上的延迟，不包含浏览器、操作系统、声卡的实际声学延迟。
完整指标定义见[输出与指标](metrics.md)，算法说明见[WSOLA 与 PLC](audio-processing.md)。

## 保存结果

播放区域可以下载所选 WAV，底部可以下载整轮汇总 CSV。其他文件保存在
`out/web/<实验编号>/run-1/`，包括逐 tick CSV、`network.csv`、`events.csv` 和配置元数据。
`OUT` 可覆盖输出根目录。生成结果不会覆盖其他实验。

服务最多保留最近 8 轮的页面访问记录，重启后需要重新生成；磁盘上的已完成结果
仍可保留。页面每策略最多预览 5000 条关键事件，超出时提示查看完整 `events.csv`。

## 实现与验证

`web/` 是无构建步骤的 HTML/CSS/JavaScript；`tools/web_server.py` 使用 FastAPI、
Pydantic、Starlette 和 Uvicorn，版本固定在 `pyproject.toml` 的 `web` 组和 `uv.lock` 中，
包来源为 PyPI。浏览器未加载第三方 CDN 脚本或字体。

服务仅监听 `127.0.0.1`，校验 Host 与请求 Origin，禁止跨站提交；参数使用严格类型、
范围、步长和交叉约束校验。调用 C++ 使用参数数组，没有 shell 拼接。单次渲染超时
120 秒，同一服务同时只运行一个实验；退出时会终止尚未完成的子进程。
文件接口只提供已完成实验中的固定结果文件，支持 WAV Range 请求以便浏览器定位。

```sh
# 将路径换为 make build 打印的实际可执行文件：
uv run --locked --group web python tools/web_test.py build/<configuration>/cmake/ajb_demo
```

该检查启动独立的临时本地服务，验证参数拒绝、同源限制、真实渲染、延迟恒等关系、
结果文件和音频分段请求，不播放声音。
